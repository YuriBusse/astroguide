# AstroGuide — следующий этап: выпуск в сеть и монетизация

## 1. Перед публикацией

- [ ] Перевыпустить `SUPABASE_SERVICE_ROLE_KEY`, если старый секрет когда-либо попадал в архивы/чат/репозиторий.
- [ ] Перевыпустить `YOOKASSA_SECRET_KEY`, если старый ключ был раскрыт.
- [ ] Создать production `.env` только на сервере.
- [ ] Поставить production URL вместо `http://localhost:5173`.
- [ ] Проверить Supabase RLS и доступ к таблице сохранённых карт.
- [ ] Проверить webhook/статус платежа YooKassa в production.
- [ ] Проверить возврат пользователя после оплаты.
- [ ] Протестировать оплату с чистого браузера и после истечения/обновления Supabase-сессии.

## 2. Архитектура для запуска

Рекомендуемая схема:

Browser → Frontend (Vercel/Netlify) → API server (Render/Railway/Fly.io/VPS) → Supabase + YooKassa

Секреты YooKassa и `SUPABASE_SERVICE_ROLE_KEY` никогда не должны попадать во frontend.

## 3. Домен

Купить короткий домен для AstroGuide и настроить:

- `https://ваш-домен.ru` — frontend
- `https://api.ваш-домен.ru` — backend API

После этого обновить `FRONTEND_ORIGIN` на production URL.

## 4. Что проверить в оплате

Проверочный сценарий:

1. Новый пользователь регистрируется.
2. Строит натальную карту.
3. Открывает Premium.
4. Нажимает «Перейти к оплате».
5. Открывается платёжная страница.
6. После успешной оплаты пользователь возвращается в AstroGuide.
7. Premium определяется сервером.
8. Полный разбор открывается без перезагрузки.
9. После выхода/повторного входа Premium остаётся доступным.

## 5. Монетизация

На первом этапе оставить одну понятную покупку:

**Полный персональный разбор — 499 ₽**

После проверки конверсии можно добавить:

- 999 ₽ — расширенный разбор;
- 1490 ₽ — разбор + PDF;
- подписку только после появления регулярной ценности.

Главное сейчас — не добавлять много тарифов. Сначала нужно проверить, покупают ли люди основной продукт.

## 6. Что добавить после запуска

### Приоритет A — обязательно

- production-домен;
- нормальная страница оплаты/успешной оплаты;
- обработка отменённого платежа;
- webhook YooKassa;
- защита API;
- rate limit;
- аналитика воронки;
- политика конфиденциальности;
- оферта;
- контакты/поддержка.

### Приоритет B — рост конверсии

- красивый preview Premium;
- 2–3 персональных примера прямо перед оплатой;
- понятный блок «что вы получите за 499 ₽»;
- отзывы;
- повторное открытие оплаченного разбора из аккаунта;
- отправка результата на email.

### Приоритет C — рост продукта

- PDF-разбор;
- совместимость двух карт;
- транзиты;
- годовой прогноз;
- реферальная система;
- промокоды.

## 7. Юридический минимум

Перед публичным запуском отдельно проверить требования к:

- оферте;
- политике обработки персональных данных;
- cookie/аналитике;
- возвратам;
- чековой документации и требованиям платёжного провайдера.

## 8. Почему первый запуск YooMoney/YooKassa мог не открыться

Если после повторного клика всё заработало, это больше похоже на разовый сбой/задержку редиректа или открытия платёжной страницы, чем на проблему с расчётом карты.

Перед production обязательно проверить:

- DevTools → Console;
- DevTools → Network;
- ответ `/api/create-payment`;
- фактический URL редиректа;
- что платёж создаётся только один раз;
- что повторный клик не создаёт несколько платежей.

Если повторится, следующим шагом нужно посмотреть конкретный ответ `/api/create-payment` — тогда можно исправить причину точно, а не обходить её.

## 9. Ближайший порядок работы

**Шаг 1:** закончить UI и Premium preview.

**Шаг 2:** проверить оплату 10–20 раз в разных сценариях.

**Шаг 3:** подключить production Supabase/YooKassa.

**Шаг 4:** развернуть frontend + backend.

**Шаг 5:** подключить домен и HTTPS.

**Шаг 6:** добавить аналитику воронки:
`карта → Premium → оплата → успех`.

**Шаг 7:** открыть сайт для первых пользователей и смотреть, где они уходят.
